### 👀 Option A — Just want to view the code? (No SSH required)

**The easiest way.** You can read files, browse notebooks and inspect a private repository in your web browser, with no terminal or SSH setup.

1. **Contact me** by email. Mention the project you're interested in, your **GitHub username**, and whether you want to view it or collaborate.
2. **I'll invite you** to the appropriate private repository using **Settings → Collaborators → Add people** (or the corresponding access settings).
3. **Accept the invitation** from GitHub, either through the notification or email.
4. **Sign in to GitHub** and open the repository link. You can browse the code directly in your browser.

> [!IMPORTANT]
> For a **personal-account private repository**, GitHub collaborators typically receive **read and write permissions**, not a separate read-only viewer role. If strict read-only access is needed, I can use a repository owned by a **GitHub organization** with the **Read** role, or share a separate code snapshot where appropriate. Please don't push changes unless we've agreed to collaborate.

### 🤝 Option B — Want to clone the repository and collaborate?

You can use **HTTPS** or **SSH** once your invitation has been accepted.

<details>
<summary><b>🌐 Method 1: Clone using HTTPS (no SSH key needed)</b></summary>

<br>

1. Accept my GitHub collaborator invitation.
2. Open the private repository while signed in.
3. Select **Code → HTTPS** and copy its clone URL.
4. In your terminal, run:

```bash
git clone https://github.com/dom00mi/REPOSITORY_NAME.git
```

Replace `REPOSITORY_NAME` with the actual repository name. GitHub will require authentication; use a supported credential manager, GitHub CLI, or a personal access token when prompted — **not your GitHub account password**.

</details>

<details>
<summary><b>🔑 Method 2: Clone using SSH (optional setup)</b></summary>

<br>

**Step 1 — Generate an SSH key on your own computer** (if you don't already have one):

```bash
ssh-keygen -t ed25519 -C "your-github-email@example.com"
```

Accept the default location if appropriate, and set a passphrase for better security. If a key already exists at that location, **do not overwrite it**; use the existing key or choose another filename.

**Step 2 — Copy your public key** (`.pub`, never the private key):

| System | Command |
|:--|:--|
| macOS | `pbcopy < ~/.ssh/id_ed25519.pub` |
| Linux | `cat ~/.ssh/id_ed25519.pub` |
| Windows PowerShell | `Get-Content ~/.ssh/id_ed25519.pub \| Set-Clipboard` |

**Step 3 — Add it to your own GitHub account:**

Go to **GitHub → Settings → SSH and GPG keys → New SSH key**, paste your **public key**, and save it.

**Step 4 — Verify your GitHub SSH connection:**

```bash
ssh -T git@github.com
```

**Step 5 — Request repository access:**

Send me your GitHub username. I'll invite your account through **Repository → Settings → Collaborators → Add people**. Accept the invitation.

**Step 6 — Clone the repository:**

```bash
git clone git@github.com:dom00mi/REPOSITORY_NAME.git
```

Replace `REPOSITORY_NAME` with the actual private repository name. **Never send me your private SSH key.** You also don't need to send me your public key for ordinary GitHub collaborator access; it belongs on your GitHub account.

</details>

<details>
<summary><b>🛠️ For automated systems: deploy keys</b></summary>

<br>

For a server or CI system rather than a human collaborator, a **deploy key** may be appropriate:

1. Generate a dedicated SSH key pair on the target machine.
2. Open the relevant repository's **Settings → Deploy keys → Add deploy key**.
3. Add the **public** key only, leaving write access disabled unless strictly necessary.
4. Configure the automated system to use its corresponding **private** key securely.

Deploy keys are repository-specific; use a dedicated key per repository. This is **not necessary** for browser-based viewing.

</details>
